方太西北服务产品达成看板 · 家里电脑更新手册

适用版本：2026-10（多月架构，含自检 / 一键脚本） · 更新日期 2026-10-05

一句话流程：把当月月报 Excel 丢进文件夹 → 双击/运行 run_update.py 一条命令 → 自动更新看板并发布上线。

一、先搞清楚：这套东西分两块

用途说明
看板本体
dashboard.html		 单文件网页，所有数据都写在里面（1–12 月全部月份）。不要手工改它，数据由脚本注入。
更新工具
一堆 _*.py		 从 Excel 读数据 → 算出各维度指标 → 注入看板 → 发布。每天/每次更新用的就是这套。

二、第一次在新电脑上用（只做一次）

1
把整个文件夹拷过来。办公室电脑上的工作文件夹，整体复制到家里电脑任意位置。
要保证这些内容都在（缺一个都会跑不起来）：
dashboard.html ← 看板本体（最新） run_update.py ← 一键更新脚本 build_dashboard.py ← 服务月/周期的公共算法库 _gen_month.py _gen_workorder.py _gen_valueadded.py _gen_valueparts.py _gen_bigcare.py _gen_extend_time_months.py _gen_cleaning.py _gen_monthly_four.py _merge_month.py _inject_month.py _reinject_monthlyfour.py _reinject_extendtime.py _reinject_cleaning.py _selfcheck_source.py _bump_build.py _gh_push.py _monthly_four.json _extend_time.json _cleaning_data.json _valueparts_daily.json 增值产品填写模板.xlsx ← 产品目录模板（增值产品 / 增值配件明细要用） publish_gh\ ← 发布目录（内含 index.html） 方太看板_家里电脑更新手册.html ← 本文档
⚠️ 那 4 个 json 一定要带（_monthly_four.json 等）：它们是"累积状态"，里面存着 1–9 月的历史。漏了会导致年度累计数变小。
另：这个包里已经全部装好了，正常不需要你手动挑文件——整个文件夹原样使用即可。
2
装 Python。到 python.org 下载 3.11 或更新版本，安装时务必勾选 Add python.exe to PATH。
装完后打开命令行（在本文件夹的地址栏输入 cmd 回车），执行： 
pip install openpyxl
看到 Successfully installed openpyxl-... 就成。
3
准备发布令牌（只需一次）。看板要推到 GitHub Pages 需要一把"钥匙"。
登录 GitHub → 头像 → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic) → 勾选 repo → 生成后复制（形如 ghp_xxxx）。
在本文件夹里新建文件 .gh_token（注意前面那个点），用记事本把令牌单独一行粘进去保存，不要有空格空行。
⚠️ 不要直接把办公室的 .gh_token 拷过来——那是办公室的钥匙，各建各的。

三、以后每次更新（三步）

1
把最新月报 Excel 放进这个文件夹（如 2026年10月西北服务产品.xlsx）。
Excel 里必须有 7 张表：服务产品收入统计、CSM服务项目、CSM配件、WMS网点买断配件明细、工单自购配件明细、工单、服务技师。
2
打开命令行。在文件夹空白处 Shift+右键 → "在此处打开 PowerShell 窗口"，或地址栏输入 cmd 回车。
3
跑这一条命令： 
python run_update.py --excel "2026年10月西北服务产品.xlsx" --cut 2026-10-04
--cut 怎么填：统计截止日 = 你拿到这份 Excel 那天的前一天（铁律）。
比如今天 10/5 导出 → 写 2026-10-04；今天 10/12 导出 → 写 2026-10-11。
跑完约 20 秒，看到最后的 完成 汇总就成功了。
只想本地看效果、暂不上线，加一个参数： 
python run_update.py --excel "..." --cut 2026-10-04 --no-publish
看效果：双击本文件夹的 dashboard.html 就能看；线上地址 https://mouren2580.github.io/fangtai-dashboard/，按 Ctrl+Shift+R 硬刷新。

四、这条命令自动干了什么（8 步）

#步骤作用 / 你要关注的
1环境检查看 openpyxl 有没有装好。
2源表自检不依赖生成结果，直接从原始明细复算：11 项检查（周期覆盖 / 结构 / 三元勾稽 / 品项还原 / 止回阀 / 单调性）。有疑点会直接停下，先把报错告诉小Buddy。
3自动备份生成 _bak_*_日期时间 系列备份，跑坏了可以改回来。
4生成 7 个维度月度矩阵 / 工单防火阀 / 增值产品 / 增值配件明细 / 大保养 / 延保年限 / 清洗保养。
5合并 + 注入把当月数据并进 _monthly_four.json 并重算年度累计，再写进 dashboard.html。
6校验核对"统计截止日""默认打开月份""内联脚本语法"，任一项不过不会发布。
7发布 GitHub Pages刷新 BUILD 号 → 同步发布目录 → 推送。
8汇总打印工单数、网点数、防火阀占比、增值产品数、大保养占比，方便你当场核对。

五、生成算法与口径（核心）

1. 服务月怎么算

不是自然月。规则：每月 28 日及以后，算进下一个服务月。

服务月实际日期区间天数
2026-087/28 – 8/2731
2026-098/28 – 9/2731
2026-109/28 – 10/2730
2027-01（特例）上一年 12/28 – 1/2731

所以导出 9/30 的数据时，它属于 10 月服务月，不是 9 月。run_update.py 会根据 --cut 自动判断，不用你操心。

2. 时间取哪一列（关键，容易搞错）

源表按哪一列判断日期
工单服务完成时间（不是创建时间！）
CSM服务项目录入完成时间
CSM配件录入完成时间
WMS网点买断配件明细发货时间
工单自购配件明细录入完成时间

脚本按表头名字找列，所以源表列顺序变了也不怕。

3. 收入口径

  • 以 服务产品收入统计 主表的「合计」为准，共 15 个品项：清洗保养、延保服务、清洁耗材、止回阀、装饰罩、水/气路金属软管、排烟出风管、水气路通用辅材、其他产品线专用、其他水路辅材、其他气路辅材、橱柜类辅材、燃气管快速接头、工具、电路辅材。
  • 网点买断原样计入，不剔除"调整"行、不剔除虚拟网点/虚拟技师。
  • 三元勾稽（自检核心）：
    CSM配件 + WMS网点买断 + CSM服务项目 ＝ 服务产品收入统计「合计」
    每月自检都会验一次，差额必须是 ¥0.00。

4. 几个专项口径

指标口径
防火阀占比止回阀数量 ÷ 烟机安装量（工单表）
止回阀（特殊）CSM配件表：销售分类=止回阀 且 上缴金额>0 的行计数（剔除金额 0/空/非数字）
清洗保养CSM服务项目表筛「销售分类=清洗保养」，剔除 保养超范围收费、灶具保养；免费＝上缴 0，收费＝上缴>0
大保养占比大保养台数 ÷ 清洗保养总单数
延保服务CSM服务项目表「销售分类=延保服务」。套餐只有 1 年 / 2 年 / 3 年 三档
增值产品CSM配件表
增值配件明细CSM配件表 + 工单自购配件明细

5. 同比（去年同月）

口径是 去年同服务月整月（如 2026-10 对 2025.9.28–10.27），取 3+1 四项：清洗保养 / 延保服务 / 清洁耗材 / 止回阀。

⚠️ 这部分没法从 Excel 自动算出来，需要人工提供：6 个办事处 × 4 项金额（新疆/宁夏/兰州/包头/呼和浩特/西宁）。
每月月初小Buddy 会问你一次，拿到后写进看板的同比表。月初同比显示很低是正常的——"几天比一整月"，随数据累积会收敛。

6. 显示规则

  • 所有百分比保留两位小数（如 18.39%，不写 18.4%）。
  • 配色按国内惯例：涨＝红、跌＝绿。
  • 角标"数据覆盖至 Y"＝--cut 你填的日期，脚本不会自己往后滚。

六、跑完怎么核对（30 秒）

  1. 命令最后一段会打印 工单数 / 网点数 / 工程师数 / 防火阀占比 / 增值产品数 / 大保养占比——和自检结果对一下。
  2. 自检里那行 三元勾稽差额 必须是 ¥0.00。
  3. 浏览器打开 dashboard.html，看顶部角标日期是不是你填的 --cut。

七、报错怎么办

现象处理
python 不是内部或外部命令装 Python 时没勾 PATH，重装并勾选；或重启命令行。
No module named openpyxl没装依赖：pip install openpyxl。
ModuleNotFoundError: build_dashboardbuild_dashboard.py 没跟着拷过来，补上即可。
自检出现 [疑点]先别继续。把红色那段截图发给小Buddy 确认，多半是源表导出问题时。
校验提示"统计截止日没找到"注入没成功，把完整输出发小Buddy。
发布报 401 / 未提供令牌.gh_token 没建好或有空格；令牌要勾 repo 权限。
线上打开是旧数据Ctrl+Shift+R 硬刷新，或换无痕窗口。
家里打不开 github.io家庭宽带访问 GitHub 不稳定，换手机热点试试。
想撤回这次更新把 _bak_dashboard_<时间戳>.html 改名回 dashboard.html，再重跑命令发布。

八、两点务必知道

1. 家里只能更新 GitHub Pages。
另一个分享链接 https://fangtai-service-dashboard.app.workbuddy.host/ 是要在办公室的 WorkBuddy 里发布的，家里电脑没有这个工具。
处理办法：家里更新完，回办公室跟我说一声"同步一下应用分享"，我补一次就行；或者家里干脆先用 --no-publish 只更新本地，回来一起发。
2. 谁最后同步，线上就是谁的数据。
家里和办公室是同一套逻辑、同一个仓库。如果两边都改过，以最后一次推送为准。建议同一时间只在一个地方更新。
