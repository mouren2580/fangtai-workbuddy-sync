二、周期口径

  • 服务月：通用规则 = 上月 28 日 → 当月 27 日。
    特例：1 月 = 25.12.28–26.1.27；2 月 = 26.1.28–2.25；3 月 = 2.26–3.27；4 月 = 3.28–4.27。
    当前 9 月 = 2026.8.28 – 9.27（31 天）。
  • 服务年：2025.12.28 – 2026.12.27。
  • 统计截止日 = 更新日 − 1（D−1 铁律）。若未通知更新，则冻结在上一次截止日、不自动滚动。
    例：9/26 更新 → 截止 9/25。
  • 时间进度 = 已过天数 ÷ 服务月总天数。例：截止 9/25 → 29 ÷ 31 = 93.55%。
⚠️ 服务月归属必须用 service_month_of(d)，不要用 d.year, d.month 直接推。 规则：d.day >= 28 → 归属到下一个月（如 8/28 属 9 月服务月）。历史上曾因直接取月份把 8/28 误判成 8 月。

三、目标口径

  • 整体目标 = 15 个品项的目标合计。
  • 三大爆品 = 清洗保养 + 延保服务 + 清洁耗材（三类合并为 1 个数）。
  • 办事处年目标（合计 ¥495 万）：新疆 187 / 宁夏 124 / 兰州 93 / 包头 39 / 呼和浩特 36 / 西宁 16（单位：万元）。
  • 达成率 = 实际 ÷ 目标；120% 目标 = 目标 × 1.2。
  • 目标在源表里没有，是看板里可编辑的（管理密码 fangtai2026）。
⚠️ 目标 _stamp 必须与目标数值同步 bump。EMBED_TARGETS_BY_MONTH[月]._stamp 是「浏览器本地存的旧目标」与「HTML 内嵌的新目标」的合并键，新者优先； 只改数值不 bump，老端会一直显示 ¥0。注意它与「数据更新于 _stamp」是两个不同字段。

四、各模块计算逻辑

1. 整体达成（办事处 · 网点明细）

实际合计 = 服务产品收入统计中 各网点 × 品项 金额合计（按【数据来源】列「合计」求和）
达成率 = 实际合计 ÷ 整体目标

2. 三大爆品

实际 = 清洗保养 + 延保服务 + 清洁耗材 三项实际合计
达成率 = 实际 ÷ 三大爆品合并目标

3. 工单 / 服务量

  • 工单数 = 工单明细行数（服务完成时间落在服务月周期内，按工单编号去重）。
  • 支持按 办事处 / 产品组 / 服务项目 / 工单类型 分组查看（办事处 → 网点 → 工程师 三级下钻）。

4. 防火阀（止回阀）占比

止回阀数量 = CSM配件表中「销售分类 = 止回阀」且「上缴金额 > 0」的 数量(S列)之和
　（金额为 0 / 空 / 非数字一律剔除）
烟机安装量 = 工单表中「产品组 = 吸油烟机」且「服务项目 ∈ {安装, 改装, 油烟机预埋烟管}」的工单量
防火阀占比 = 止回阀数量 ÷ 烟机安装量 × 100%
⚠️ 易错点：止回阀取 数量列(S)求和，不是行数计数。支持 办事处 / 网点 / 工程师 三维度查看。

5. 增值产品

  • 源：CSM配件表 + 工单自购配件明细。
  • 日期过滤以 「录入完成时间」 为准（CSM配件 AK 列 / 自购 K 列）——与工单模块用「服务完成时间」不同。
  • 普通品项按「配件编码/名称匹配」计数；其中 止回阀 走特殊口径（同第 4 条）。
  • 全区总计数 = 各品项计数之和。

6. 增值配件（时间窗口）

  • 窗口：昨日 / 近 3 日 / 近 7 日 / 当月（以统计截止日为基准回算）。
  • 各品项计数 + 覆盖工程师数。
  • 数据来自按日累积存储（_valueparts_daily.json，结构 months:{月:[{d,k,o,p,s,q}]}），窗口按日期范围从存储里聚合。

7. 大保养占比

分母 = 销售分类 = 清洗保养 的行数，剔除「保养超范围收费」「灶具保养」
分子 = 「油烟机大保养」+「油烟机大保养升级包」单数（只计单量，与金额无关）
占比 = 分子 ÷ 分母

8. 延保服务

  • 源：CSM服务项目表，销售分类 = 延保服务。
  • 按「服务收费项目」拆年限：含"一年"→ y1、含"两年"→ y2、含"三年"→ y3。
  • 按「录入完成时间」落在服务月周期内。
  • 指标：单数 + 上缴金额合计；时间窗口：昨日 / 近 3 日 / 近 7 日（以统计截止日为 cut）。
  • 排序规则：数量降序 → 数量相同时按金额降序；金额一律保留两位小数。

9. 清洗保养

  • 源：CSM服务项目表，销售分类 = 清洗保养。每行 = 1 单；数量 = 行数；金额 = 上缴金额(Y列)。
  • 免费单 = 上缴金额 = 0；收费单 = 上缴金额 > 0。
  • 免费/收费统计仅含主保养四项：油烟机小保养、油烟机大保养、集成灶小保养、集成灶大保养（其余如"保养超范围收费""灶具保养"不计）。
  • 维度：办事处 / 服务网点 / 服务工程师（各维度带合计行）。
  • 主项选择器：全部 / 4 个单项（选单项时明细表只显示数量列）。

★ 10. 全区品项分析（环形图 + 条形图 + 查看范围）— 本次重点

  • 位置：模块 2「📦 全区各品项分析」。
  • 环形图：纯 SVG 手绘（无任何外部依赖 / CDN，离线可用）。
    • 扇区按品项实际收入降序排列；中心显示当前范围合计金额。
    • 绘制方式：每个扇区是一个 <circle>，用 stroke-dasharray + stroke-dashoffset 画弧，transform="rotate(-90 cx cy)" 从 12 点方向起画。
    • 右侧图例 = 色点 + 品项名 + 金额 + 占比（占比两位小数）；爆品带 🔥 标记。
    • 无收入的品项不绘制扇区，在图例下方以灰字列出「本月无收入，未绘制：…」。
  • 查看范围切换（#itemScopeSeg）：全区 + 6 个办事处共 7 个按钮（pieOffice 变量，空串=全区）。
    • 切换后：环形图、图例、条形图、下钻明细全部同步切换口径，文案里「占全区」会变成「占新疆」等。
    • 切到某办事处后，下方明细表中该办事处所在行高亮（tr.hlRow）。
  • 下钻：点击 环形扇区 / 图例行 / 条形图行 均可，展示「该品项各办事处分布」（实际 + 占该品 + 分布条）。
  • 品项配色固定：PIE_COLORS 按品项在 ITEMS 中的下标取色（pieColorOf()）， 保证同一品项在 环形图 / 图例 / 条形图 / 明细 中颜色一致。

11. 下钻（办事处 → 网点）· 目标差值 KPI

距离 100% 差值 = 目标 × 1.0 − 实际　　距离 110% 差值 = 目标 × 1.1 − 实际　　完成 120% 差值 = 目标 × 1.2 − 实际
剩余每天需完成 = 差值 ÷ 剩余天数（剩余天数 = 服务月天数 − 已过天数）
日均完成金额 = 实际 ÷ 已过天数
  • 当差值 ≤ 0 时显示「已达成」。
  • 着色见第六章（近绿远红渐变）。年度视图下无「剩余天数」概念，这组 KPI 隐藏。

12. 年度累计视图

  • 1–N 月各月数据合并展示；统计截止日取各月中的最大值。
  • 年度目标进度按服务年（12.28–12.27）计算时间进度，与月度进度相互独立（年度目标色用 yearTimeProg()，勿用月度 TIME_PROG）。

五、调平约定

【数据来源】列中的「网点买断」与「调整（虚拟网点 / 虚拟技师）」原样计入——按「合计」列求和，表里写什么就显示什么，不做任何剔除。

六、配色与显示约定

  • 涨红跌绿：红色 = 增长/达成，绿色 = 下降（中国习惯，不要用欧美口径）。
  • 目标差值卡着色（2026-09-12 增强后，当前逻辑）：
    已达成（差值 ≤ 0）→ 固定绿 hsl(140,72%,40%)，底色 hsl(140,70%,93%)
    未达成 → ratio = 实际 ÷ (目标 × 档位)（档位 = 1 / 1.1 / 1.2）
    　　hue = clamp(0, 120, ratio1.4 × 120)　← 指数 1.4「调陡」，红区更大、过渡更集中
    　　文字色 hsl(hue, 90%, 38 + ratio×14 %)　← 高饱和 + 越接近目标越亮
    　　卡片底色 hsl(hue, 85%, 95%)，并在卡片左侧加 5px 同色色条
  • 百分比两位小数铁律（2026-09-21 锁定）：全看板百分比一律精确到小数点后两位（18.98%，不写 18.9%、不写 19%）。
    唯一入口：const pct = x => (x*100).toFixed(2) + '%';（在 ~851 行，带锁定注释）。
    新增任何百分比显示都必须走 pct()；少数不走 pct 的散点（同比 yoy、大保养明细、年度达成率、工程师「占筛选合计」）也必须 toFixed(2)。
    数据层（各 _gen_*.py）统一 round(x*100, 2)，勿改成 1 位。
    自检命令：业务行（行长 < 3000）里 grep toFixed(1) 应为 0 命中。

八、更新与部署流程

8.1 数据更新（推荐：一键封装）

_build.py --excel "…2026年X月西北服务产品.xlsx" --date <截止日>
_release.py --excel "…" --date <截止日>　← 再自动加上 构建 → bump → 推送 → 线上校验
  • --date = 数据截止日 = 更新日 − 1（D−1 铁律），脚本据此推导服务月与周期。
  • 一键封装内部已按正确文件名生成各中间文件，不要逐条手跑生成器。

8.2 手动分步（排障用）——每个生成器都必须传 --out

_gen_month.py <excel> --date <cut> --out _month_<YYYY-MM>.json　← 注意不是 _month.json！
_gen_workorder.py <excel> --date <cut> --out _mf_<YYYY-MM>_wo.json
_gen_valueadded.py --lo <服务月起> --hi <cut> --excel <excel> --out _mf_<YYYY-MM>_va.json
_gen_valueparts.py --svc-lo <服务月起> --cut <cut> --excel <excel> --month <YYYY-MM> --out _mf_<YYYY-MM>_vp.json
_gen_bigcare.py --excel <excel> --ps <服务月起> --pe <服务月止> --out _mf_<YYYY-MM>_bc.json
_gen_extend_time_months.py --excel <excel> --svc-lo <服务月起> --cut <cut> --month <YYYY-MM>
_gen_cleaning.py --excel <excel>
→ 然后：_merge_9.py → _reinject_monthlyfour.py → _inject_month.py --default-month <YYYY-MM> → _reinject_extendtime.py → _reinject_cleaning.py
⚠️⚠️ 漏传 --out 的两处静默陷阱（2026-09-26 实际踩过，不报错但拿旧数据算）：
  1. _gen_month.py 默认写 _month.json，而 _inject_month.py 是 glob("_month_*.json") 按文件名取月份 → _month.json 根本匹配不上，_month_<月>.json 保持旧值 → D 块与「统计截止日」永不更新。
  2. _merge_9.py 读的是 _mf_<月>_{wo,va,vp,bc}.json 中间文件，不是生成器默认输出 _workorder.json 等 → 会把旧中间文件再合一遍。
30 秒自检（任一命中即踩坑，别部署）：
① _bump_build.py 输出的 version.json 里 cut 仍是旧截止日；
② 合并脚本打印的合并前/后 year 工单总数一模一样（正常应增加）；
③ dashboard.html 里 grep "统计截止日":"<新日期>" 命中 0。
