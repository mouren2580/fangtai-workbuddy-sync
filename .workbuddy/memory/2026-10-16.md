# 2026-10-16 第二轮：手机显示 8 月 → 修缓存穿透（BUILD `20261016-0905`）

## 现象
「手机打开链接显示到8月了，你在检查下，默认显示当月数据，10月」

## 排查
1. 先排除服务端：`curl` 两条链接 → `var BUILD = "20261016-0846"` / `let CURRENT_MONTH = "2026-10"` **都正确** ✅
2. 代码逻辑也正确：`MONTH_DATA` 含 `"2026-10"`；初始化 `applyMonth(CURRENT_MONTH)`；`SAVED_MONTH` 初始也是 `2026-10`。
   → 结论：**手机端缓存的旧 HTML 没被换掉**（8 月版，`CURRENT_MONTH=2026-08`，用基准块 DASHBOARD_DATA）。
3. 缓存穿透块里找到根因：
   ```js
   var n=parseInt(sessionStorage.getItem('_cbN')||'0',10);
   if(n>=2) return;      // 次数用尽 → 直接退出
   ```
   **微信/QQ 内置浏览器的 sessionStorage 长期不清除**，累计 2 次后就永久 return，缓存穿透彻底失效 → 之后每次更新手机都看不到。

## 修复
改为「按版本号去重」：`localStorage['_cbTried']` 记录已尝试过的服务端版本，**每个新版本自动重载一次**；
同一版本已尝试过仍不一致才走人工提示（红色顶部条：`发现新版 xxx（当前显示 yyy）→ 点此刷新`，点击 `location.reload(true)`）。
→ 既不会死循环，也不会因历史累计次数而卡死。
改动落在 `/*__CACHEBUST_START__*/…/*__CACHEBUST_END__*/`，**4 份 HTML 含底板 `dashboard_ref.html` 一起改**（各份 BUILD 值不同，Edit 时 old_string 要带各自的 BUILD：三副本 `20261016-0846`、底板 `20261005-0932`）。

## 本轮踩坑
0. **`str.rindex(sub, i)` 会向后搜**：提取 script 段时写成 `src.rindex('<script>', i)`（i=CACHEBUST 位置）会搜到 CACHEBUST_END **之后**的 script，
   切出空串 → `substring not found`。必须写成 `src.rindex('<script>', 0, i)` 限定在前缀内。
1. **误判 git 提交失败**：`git add -A && git commit -q …&& git push` 输出「nothing to commit, working tree clean」，看着像提交失败，实际 **commit 已成功**（HEAD `5f04226`），只是 `&&` 短路导致 push 没跑。
   → 判断依据永远是 `git log -1` / `git rev-parse --short HEAD`，别信 commit 回显；push 与 commit **分开写命令**。
2. **`git rev-parse HEAD origin/main github/main` 报 `fatal: Needed a single revision`**：远端跟踪分支不存在时会连带让整条命令失败，别把多个 ref 塞进一条 rev-parse。
