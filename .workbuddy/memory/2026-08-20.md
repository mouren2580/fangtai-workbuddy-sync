## 修复"剩余时间天数不对"（2026-08-20 续2）
- 用户诉求：打开 `mouren2580.github.io/fangtai-dashboard/`、手动同步 Excel 后，看板的"剩余天数"显示不对。
- **定位根因**（两层）：
  1. 之前"从过账日期取最大值当截止日"的逻辑读的是「服务产品收入统计」表，但该表**根本没有日期列**（表头为 大区/服务中心/办事处/服务网点/.../合计）。其余 4 表（WMS/CSM服务/CSM配件/工单自购）才有"录入完成时间/发货时间/传输时间/预约上门时间"等日期列。`maxDate` 恒为 null → 兜底写死 `2026-08-19`。
  2. `rebuildFromWorkbook`（同步Excel入口）**不重新算 `DEFAULT_ASOF`**，沿用页面加载时的旧截止日 → 同步新数据后"已过/剩余天数"永远不更新。这是用户感觉"不对"的主因。
- **实测正确值**：当前 Excel 全表日期列最大值 = 2026-08-19 23:00:06（来源：WMS「传输时间」）。服务周期 7.28–8.27（共31天）→ 截止 8/19 时 已过23 / 剩余8。即就"数据到8/19"而言 剩余8 数学正确，但口径是否被用户认可需确认（见下）。
- **修复**：
  1. 新增 `deriveCutoffFromWorkbook(wb)`：遍历所有 sheet 的"日期/时间"列取全局最大日期，封顶今天（防未来日期）。
  2. 内嵌加载处改用 `deriveCutoffFromWorkbook` 取代失效的过账日期逻辑。
  3. `rebuildFromWorkbook` 同步后调用 `deriveCutoffFromWorkbook(wb)` 重算 `DEFAULT_ASOF` 与 `DASHBOARD_DATA.meta.统计截止日`，再 `computeTime` → 同步新 Excel 后剩余天数随数据更新。
- **部署**：改 `dashboard_offline.html` → cp `deploy_cs/index.html` → 重部署 CloudStudio（同址）；克隆 `fangtai-dashboard` 浅克隆 → 替换 `index.html` → commit `39f7f10` → push（`d5e20ca..39f7f10`）。GitHub 443 抖动多次重试后成功。
