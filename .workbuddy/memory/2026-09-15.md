参考 `dashboard.html` 与工作区 `dashboard_offline.html` **变量结构完全相同（各 124 个顶层声明）**，
但参考版多出/更新了 4 个块：
- `MONTHLY_FOUR` = `{months:{ "2026-01".."2026-09": {workorder, valueadded, valueparts, bigcare} }, year:{...}}`

- valueparts：昨日 88 / 近3日 337 / 近7日 749 / 当月 1571 **全中**
- bigcare：397 / 388 / 11 / 2.84% **全中**；`net`/`eng` 明细（含合计行）也一致
- EXTEND_TIME_DATA：104 条、合计 ¥39,448.30 — **多重集完全一致**
- CLEANING_DATA：387 条 — **多重集完全一致**
- MDATA_B、MDATA_W 逐字节 IDENTICAL

## 关键坑（下次务必注意）
1. **排序**：大保养 `net`/`eng` 的同值排序用**首次出现顺序**（不是名称），合计行文案固定为
   `[合计]全区` / `[合计]全部网点` / `[合计]全部工程师`。
2. **meta 标签不统一**（照抄参考即可）：`workorder.meta.截止` = 服务月末（9-27）；
   `MONTHLY_FOUR.bigcare.meta.截止日` = 服务月末；`MDATA_*_B.meta.截止日` = 截止日（9-14）且**无「周期」字段**；
   `workorder.meta.周期` 固定 `YYYY-MM-DD~YYYY-MM-DD` 服务月末。
3. **延保**：`EXTEND_TIME_DATA` 记录里 `c` 恒为空串（参考版如此），E 块 `techs[].id` = 姓名（不是编码）；
   E 块必须由已过滤的 `rec_et` 聚合，不能用 gen_extend（它不过滤日期）。
4. `valueadded.products[]` **有** `verify` 字段（油杯垫=部分编码未匹配提示、止回阀=特殊口径）；
   `valueparts.products[]` **没有** `verify`。
5. 明细表（EXTEND_TIME / CLEANING）按源表行序，跨文件不可复现完全一致的排列——只需校验「多重集一致」。
6. `MDATA_2026_08_*` 不存在是正常的：8 月用基准块 `DASHBOARD_DATA/TECH_DATA/...`。
